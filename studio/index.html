    Cliquez sur « Vérifier » : les erreurs du DSL s'affichent ici, avec le fichier, le chemin et la correction suggérée.

    Cliquez sur « Compiler » : la sortie PHP + JS + CSS est produite en mémoire, téléchargeable en zip, et l'aperçu montre la version texte de chaque page.

    Chaque envoi est signé (HMAC-SHA256, horodaté) ; le serveur vérifie chaque fichier contre le manifeste d'empreintes avant de remplacer la version en place. Données, cache et .env du serveur sont conservés. Le secret reste dans cet onglet.

    
    
    
    
      Choisissez un composant.
      
    
      
      
      Structure : site.yaml (identité, nav, thème, coordonnées), pages/<id>.page.yaml (une page par fichier : route, seo, sections), assets/ (images), et selon le site segments.yaml, data/products.yaml, brief.md, custom/.
      
      
      Section = un objet avec une seule clé, le nom du composant, et ses props dessous. Toute section accepte id (ancre), keywords (recherche) et variants (personnalisation).
      
      
        
        
      • Piège n° 1 : en notation { a: x, b: y }, une virgule ou un deux-points dans un texte coupe la valeur. Texte long → notation bloc ou guillemets.
        • 
        
      • Piège n° 2 : un # précédé d'un espace commence un commentaire. Ancre seule ou couleur toujours entre guillemets : "#contact", "#6b2d5c".
        • 
        
      • Un lien est toujours { label: Texte, to: cible } ; to est une route déclarée, une ancre, ou une URL https:, mailto:, tel:.
        • 
        
      • N'inventez ni prix, ni délai, ni distinction absents du brief : écrivez [à compléter], la compilation le signale.
        • 
      
      
      
      Équivalents en ligne de commande : node bin/sitec.js check | build | catalog | explain | review | keywords | host | deploy.
      
      
      Après déploiement : le back-office du site est sur /_admin (jeton ADMIN_TOKEN), la version texte sur /lisible…, le jumeau pour agents sur /site.json et /llms.txt.
